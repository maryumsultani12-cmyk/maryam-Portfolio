Case Study — 01

Lab Automation System.

A web-based system built to move appliance testing, product requests and testing records off paper and into one connected workflow.

HTMLCSSBootstrapJavaScriptPHPMySQL
Overview

Why it exists.

A laboratory testing service handling multiple product requests at once.

The lab handled appliance testing requests manually, with records scattered across paper forms and spreadsheets. Requests were easy to lose track of, and there was no shared view for staff to see what stage a product was at.

The goal was a single web application where users could submit product requests, and lab staff could manage testing records and track each request's status through the workflow, from submission to completed report.

Product request intake
Testing record management
Status tracking per request
Role-based access (staff / user)
MySQL-backed records
Build

How it was built.

Frontend, backend and database working together as one workflow.



View on GitHub →

Frontend. Built with HTML, CSS and Bootstrap for a responsive layout, with JavaScript handling form validation and interactive elements so users get instant feedback before a request is submitted.

Backend. PHP handles the request lifecycle — creating, updating and closing testing records — and MySQL stores product requests, test results and user accounts behind it.

Workflow. Requests move through defined stages so both the requester and the lab team can see where a product currently stands, cutting down on status-check back-and-forth.

Outcome. Replacing manual tracking with a shared system made testing records easier to find, reduced duplicate requests, and gave the lab a clearer picture of its workload.
